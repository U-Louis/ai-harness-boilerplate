# 20. Limits

**Abstract principle.** Read these bounds before treating a rule in this folder as a settled lab result or as AISVS compliance. The first real product fills the constitution with real bars, then runs M0 and M1 before the full lens set.

Digest: §20.

## Bounds

- The verifier is separate from the implementer because the digest chooses that assurance split. Anthropic's November 2025 harness does not require it. The January 2026 guidance from the same organization is to start with one agent. This folder still separates P3 and P4.
- OpenAI's low-friction merge is one repository's outcome after months of tooling, and the post says it would be irresponsible at low throughput. This folder does not start there. A red invariant stays blocking even if a later constitution drops the human read.
- Playwright misses some interface classes. Native dialogs are the one the digest names. Third-party widgets that render outside the DOM the test can see belong in the evidence `limitations` line. The page's own refusals use `role="alert"` and `data-error-code` so the journey can see them.
- "Startup under 800 ms" and "no span over two seconds" are example prompts, not budgets. A latency bar names the request, the proportion, the threshold, the measurement point, and the window. A budget without a log line the agent can query is not a gate. `Model::preventLazyLoading` and a flat query count are the efficiency checks that can fail before any millisecond exists.
- No gate here proves the absence of defects. `AUDIT_PASS` means the checklist was re-run and the rows were green.
- This folder stops where a real project starts. The first product fills `complexity-score`, `diff-posture`, `instruction-model`, the storage engine, and the ASVS level, then runs M0 and M1 before investing in all six lenses on every slice.
- AISVS AC.4.1 is stricter than G4. `05-roles.md` records the departure. This folder does not claim the standard.
- A thin tool loop that matches a large harness on pass rate is a result about issue-shaped tasks. `19-evolvability.md` has the consequence. It is not a result about these gates.
- An approval on the forge is a button. `21-unattended-runs.md` says what the person looks at under Read and under Metrics. The button does not fill G4, and it does not see whether the oracle is real.
- The two-send-back cap is the digest's number. Labs published neighboring numbers (three attempts, three review rounds). The agent does not "correct" the cap to three inside a slice. A constitution change can record a different cap. Until it does, the cap is two.
- Inertia v2 and Laravel 12 calls in these files are the ones named in `README.md`. A package API these files do not name is not a rule. The agent looks up the installed version and stops if the installed method differs, instead of inventing a call.
- Desk's title length, state names, and error codes are an illustration. They are frozen only after a product spec copies them on purpose.

## What the first product does before the full harness

1. M0: constitution with the empty fields either filled or explicitly unset, edges, one error shape, one log shape, non-goals.
2. M1: one journey, the domain-boundary test, Pint, `tsc`, secret scan, `features.json`, `init.sh`.
3. Lenses: add them when the first slice has a clean GV. Six lenses on an empty repository with no spec are noise.

## What an agent does

- States the limit when it cites a rule that is a local choice (`02-claims.md`).
- Writes Playwright blind spots into `limitations`.
- Fills constitution fields instead of borrowing Desk's sample posture silently.

## What an agent refuses

- A badge, a README line, or an evidence header that says the pipeline is AISVS Level 1 or Level 2 while the recorded departure stands or the scanners are absent.
- Deleting G3 because a new model is "careful".
- Treating `AUDIT_PASS` as a warranty to the steward.
- Inventing a Laravel 13 or Inertia method so a slice matches a sentence in this folder.

## Review checks

- The constitution's unset fields match the behavior (no latency gate, no complexity block, no merge while posture is unset).
- Evidence limitations mention any dialog or widget the journey did not see.
- The pull request does not cite this folder as an OWASP certification.

## Traps

- A starter kit's tests passing on first boot is not M1. M1 is the product's submit-and-read journey.
- `php artisan test` green on `actingAs` feels like a finished feature. `20-limits.md` and `13-testing.md` both keep the journey as the done-check for a page. The limit is the same: the HTTP seam misses the screen.
- Recording "none" for limitations on a journey that never opened the refusal alert hides the blind spot. If the spec has a refusal step, the limitation line says the alert was asserted, or it says what was not seen.
